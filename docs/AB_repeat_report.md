## 逐场景配对检验（主分析）

每个场景在所有批次上的红方胜率作为一个配对观测（A 组 vs B 组，n=100 场景），
这样按场景消除了难度差异，剩下的差异才归因于构建。

| 量 | 值 |
|:---|---:|
| 红方胜率 A | 39.0% |
| 红方胜率 B | 38.0% |
| 差值 (A-B) | +1.0% |
| 配对 t 检验 | t=0.30, p=0.761 |
| Wilcoxon 符号秩 | W=1498, p=0.442 |
| 场景符号统计 | A 更好 37 / B 更好 44 / 相同 19 |

- 场景聚类 bootstrap 95% 置信区间：`[-5.4%, +7.3%]`（含 0，无法排除无差异）

## 结论

1. 修复的效果在**异常次数**上是确定的：A 组全部 0 次，B 组 21019 次。
2. 红方胜率差异 +1.0%，95% CI `[-5.4%, +7.3%]` 含 0，配对 p=0.761：**在现有批次数量下，这行修复对胜率没有可检出的影响**。它修的是「受威胁帧整帧丢决策」这一确定性缺陷，胜负层面的收益被平台自身的随机性淹没了。

## 附带观察：批次间波动

| 组 | 各批红方获胜 | 均值 | 批间标准差 |
|:---|:---|---:|---:|
| A 修复后 | 31, 48, 33, 44 | 39.0 | 8.3 |
| B 未修复 | 39, 38, 37 | 38.0 | 1.0 |

B 组三批几乎重合（37-39），A 组却在 31-48 之间散开。Levene 方差齐性检验
`p=0.003`，即两组的**批次间波动差异显著**。

一个可能的机制：未修复时异常会中断该帧决策，飞机只能沿用上一帧指令，
行为反而更"钝"、批次间更少发散；修复后受威胁帧全部正常决策，轨迹分歧更大。
但每组只有 3-4 批，这个观察只能算**初步**，需要用更多批次确认。
