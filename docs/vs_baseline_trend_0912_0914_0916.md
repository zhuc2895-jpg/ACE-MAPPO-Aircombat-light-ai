# plus vs 原版：三次重复对照（09-12 / 09-14 / 09-16）

## 口径

- 每次都是**双方向各 100 场**（plus 红/原版 蓝，原版 红/plus 蓝），标准 20 场景 x 5，同一份
  `SimuConfig.txt` / `AreaConfig.txt`。
- "命中"用**严格同帧规则**（弹与敌机在同一个 0.1 s 帧块内被删除）。
- 三个构建：`6B28BB46ADF0`（09-12）/ `30913FD36F19`（09-14）/ `A2DCE409BE32`（09-16）。
  对手始终是同一个原版基线 `E3FD10E8E77C`。

## 一、比分

| 日期 | plus 红 | plus 蓝 | 合计 | 胜率 |
|:---|:---|:---|:---|:---|
| 09-12 | 57 : 43 | 100 : 0 | 157 : 43 | 78.5% |

三次都落在 79–81%，**这个平台的单批噪声是 ±5~7 个百分点**（见 `AB_repeat_report.md`，
同构建两批红方获胜数曾相差 13 场），所以三次之间的差异不构成趋势。

僚机补射资格）**都还没有落到代码里** —— 已核对：`WTA_TARGET_MISSILE_CAP = 2`、
`WTA_FOCUS_FIRE = False`、分流仍受 `len(scored_targets) > 1` 限制，与 09-14 版逐行相同。

## 三、09-15 那次改动：蓝方防御线几何

09-15 22:05 的改动只有 **1 个 hunk、4 行**，全在 `_blue_defense_line_strategy` 里：

```
- line_lon = enemy['lon'] + (own['lon'] - enemy['lon']) * back     # back 从"敌方"端量起
+ line_lon = own['lon']   + (enemy['lon'] - own['lon']) * back     # back 改从"我方"端量起
- ... + cos(...) * 6000.0 / R ...                                  # 6000 m 侧向槽位偏置
+ ... + cos(...) * 0.0    / R ...                                  # 归零
```

**效果：测不出来。** 因为改动只影响蓝方，`plus 红` 那批（红方代码未变）天然是对照组：

| 批次 | 09-14 | 09-16 | 差 |
|:---|:---|:---|:---|
| plus 蓝（受处理） | 604 发 / 202 中 / 33.4% | 594 发 / 202 中 / 34.0% | 发射 −10，命中 0 |
| plus 红（对照） | 536 发 / 102 中 / 19.0% | 556 发 / 98 中 / 17.6% | 发射 +20，命中 −4 |

对照组的波动和受处理组同量级（发射 ±10~20），而命中数几乎没动。
**结论：这次蓝方几何改动没有可测收益，也没有可测损失。**

## 四、下一步（DLL 9/20 前）

1. 真正能动效率的还是那三条补射相关改动 —— 目前一次都没做。
   数据支持：第 3/4 发命中率 0–2%，占增量的 86%。
2. 判定指标继续用**首发命中率**与**第 3 发及以后占比**，别看总分（噪声太大）。
3. 若要继续调蓝方几何，建议一次只改一个变量并配 3 批重复，否则单批差异无法解读。
